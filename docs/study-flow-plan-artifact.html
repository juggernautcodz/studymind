StudyMind — Internal Planning Document

Study Flow & Professionalism Redesign Plan

Confirmed bugs, competitor research, and a prioritized fix plan. Nothing in this document has been built yet.
📋 Planning only — no code changed

1. Two confirmed bugs

Data bug Monthly usage tracking silently drops data

Two different implementations increment the same usage counter. The one actually running in production (middleware.ts) checks whether a row exists, then writes — instead of one atomic database update. When two transcriptions finish close together (e.g. two lectures recorded back-to-back), both requests can think no row exists yet. The second write then hits a database uniqueness rule and fails — silently. No error shown to you, no retry. That increment is just gone.

The correct version already exists in a different file (billing.ts) but is never called anywhere — dead code sitting unused while the broken version runs in production.

Misleading UX "Time to Study!" isn't based on what's actually due

The home screen card counts every flashcard you've ever created — no concept of due, overdue, or already-mastered. A card you've answered correctly five times looks exactly as "ready" as one you've never seen.

The frustrating part: a real spaced-repetition engine already exists in the backend (the same math Anki uses — ease factor, review intervals, next-review dates) built for the paid "Adaptive Review" feature. The free home screen never touches it.

2. What makes StudySmarter and NotebookLM better right now

StudySmarter

This is the closest direct competitor — same core idea as StudyMind (turn lecture material into flashcards/notes/quizzes), same $9.99/month price. What it does that StudyMind doesn't yet:

Visible mastery, not just content. It shows you a percentage of how much of each subject you've actually mastered, computed from your real review history — not just a list of things you made.

A planner that decides when you review, not just what. It schedules reviews based on how well you know each card, so opening the app tells you what's actually due today — not everything you've ever made, shuffled.

One unified screen. Notes, flashcards, quizzes, and the review schedule live together — there's no equivalent of StudyMind's disconnected Mind Map subtopics that quietly go nowhere.

Google NotebookLM

This is the more dangerous comparison, because it does StudyMind's exact core loop — upload or record source material, get auto-generated flashcards and quizzes grounded in that material — and its free tier is genuinely generous.

It's free for roughly what StudyMind charges $9.99/month for. 100 notebooks, 50 sources, 50 chats a day, at no cost — backed by Google's infrastructure, not a small team's server bill.

It shows its work. Every flashcard and quiz answer can be traced back to the exact source text with a citation — if you get something wrong, you can tap "explain" and see exactly why, pointing back to your original material. StudyMind has no equivalent right now.

It added real progress tracking in 2026 — saved sessions, mastery tracking, the ability to shuffle or delete cards with memory of what you've done. This closed the one gap that used to separate it from a "real" study app.

The honest read: StudyMind's price is fine — it matches these two almost exactly. The problem is both of them currently deliver more for that price than StudyMind does, because the two features that would justify the price — a real due-based review queue, and visible mastery — either don't work or are hidden where nobody sees them.

4. Fix priority order

  1. Fix the usage-tracking race condition
    Data-integrity bug, isolated, low-risk to fix — should not wait on anything else.
  2. Wire the home screen to real due-cards data
    Uses backend infrastructure that already exists for the paid tier — mostly a wiring change, not new engineering.
  3. Add a Library view
    One screen to browse all notes/flashcards/quizzes across every course — the single most common shape across every competitor reviewed.
  4. Surface mastery/progress
    Mostly a display problem — the underlying stats are already being recorded for the paid adaptive engine, just never shown.
  5. Decide on Mind Map, then polish
    Make "subtopics" real content or rename them so they stop implying they're the same as a real Topic — then a copy/navigation pass once the logic underneath has changed.
